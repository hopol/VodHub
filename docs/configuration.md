# 配置说明

VodHub 的所有配置都存在 SQLite 里（`runtime/data.db`），**没有配置文件要改**，全部在后台可视化设置。

## 运行期配置

`config.php` 顶部定义了少量常量，**一般不用改**。如果你的环境有特殊需求可以调整：

```php
// 站点名称（可在后台改，这里只是兜底默认值）
define('APP_NAME', '影视聚合站');

// 运行期目录（数据库 + 缓存）。需要可写，且不要对 Web 公开
define('DATA_DIR', __DIR__ . '/runtime');
define('DB_FILE',  DATA_DIR . '/data.db');
define('CACHE_DIR', DATA_DIR . '/cache');

// 缓存有效期（秒）
define('CACHE_TTL',      1800);   // 列表 / 详情：30 分钟
define('CACHE_TTL_TYPE', 86400);  // 分类：24 小时

// 会话 cookie 名（改这个可以避免与同域名其他应用冲突）
define('SESSION_NAME', 'vodsite_sid');

// 首次安装的管理密码（已在后台改过则失效）
define('DEFAULT_ADMIN_PASSWORD', 'admin123');

// ---- 极致低功耗模式（1.3.0 新增）----
// 上游失败的负缓存：这段时间内完全不出站（消灭故障放大器）
define('CACHE_TTL_NEG', 60);
// 页面静态缓存目录 —— 必须在站点根目录下（.htaccess 用相对路径 rewrite 到这里），
// 不能放进 runtime/（那里被 .htaccess 整个 [F] 拦掉）
define('PAGE_CACHE_DIR', __DIR__ . '/c');
// 图片代理本地缓存目录，可被 Web 直接访问
define('IMG_CACHE_DIR', __DIR__ . '/static/imgcache');
```

### 为什么要分两级 TTL

- **分类（`ac=list`）几乎不变** —— 走 24 小时长缓存，大幅减少上游请求
- **列表 / 详情常更新** —— 走 30 分钟，保证新片能出现

上游故障时会**自动降级使用旧缓存**，不会直接白屏。

### 改了不生效？

`config.php` 是普通 PHP 文件，改完立即生效（不像 `settings` 表需要通过后台写入）。

> `display_errors` 在 `config.php` 末尾默认开启。**生产环境建议关掉**：
> ```php
> ini_set('display_errors', '0');
> ```

## 后台设置项

### 📡 数据源管理

| 字段 | 说明 |
|------|------|
| **名称** | 前台顶栏标签显示的名字，50 字以内 |
| **接口地址** | 苹果 CMS `provide/vod` 格式，**填到 `at/json/` 这一级**，程序会自动拼参数 |
| **排序** | 越小越靠前。前台源标签按此排序 |
| **备注** | 仅自己可见的说明（如"备用线路"） |
| **使用模板** | 给这个源单独绑定模板；「站点默认」= 跟随后台的默认模板 |
| **所属分组** | 选一个分组；「未分组」会归到末尾的「全部」标签 |
| **启用该数据源** | 取消勾选后前台不再展示，但配置保留 |
| **启用图片代理** | 上游有防盗链时打开 |
| **图片域名白名单** | **留空 = 不限制域名**（内网仍自动拦截）。想加严就填，逗号分隔 |

**操作按钮**：

| 按钮 | 作用 |
|------|------|
| 测试 | 请求上游，返回延迟与是否拿到内容 |
| 识别图域 | 从该源最近 10 条内容里提取图片域名，自动写入白名单 |
| 启用/关闭 | 快捷开关，等同于编辑表单里的勾选框 |
| 编辑 | 展开完整编辑表单 |
| 删除 | 删除数据源（会先清掉它的缓存） |

### 🗂 数据源分组

源超过 5 个后顶部标签会很挤，分组后按组归类显示。

| 操作 | 说明 |
|------|------|
| 改名 | 组名可随时改，不影响组内数据源 |
| 排序 | 越小越靠前 |
| 删除 | **组内数据源会自动归入「未分组」**，不会被删 |

> 分组只影响前台展示归类，不会删除或停用任何数据源。

### 🎨 模板管理

| 设置 | 说明 |
|------|------|
| **站点默认模板** | 所有**未单独绑定**模板的数据源用它 |
| **已安装模板列表** | 显示目录名、名称、封面模式、说明、是否为站点默认 |
| **简单样式编辑** | 改主题色 / 悬停色 / 圆角 / 封面比例 / 列数 |
| **恢复默认样式** | 清空该模板的所有自定义样式 |

样式编辑的机制与自定义模板时的注意事项 → [模板开发](templates.md#css-变量编辑器)

**编辑框只显示当前模板「真正会被用到」的维度** —— 某个维度没出现，是模板 CSS 里没有 `var()` 引用它，属正常。

### 🔐 访问设置

| 设置 | 说明 |
|------|------|
| **启用访问密码保护** | 开启后，任何人打开前台都要先输密码（后台登录不受影响） |
| **访问密码** | **留空 = 保持原密码不变**。首次必须填写才能启用 |
| **修改管理密码** | 需要先验证原密码，新密码至少 6 位 |

> **如果勾了启用但没设密码**，系统会自动关掉保护并提示「尚未设置访问密码，无法启用保护」—— 避免把自己锁在外面。

### ⚙️ 站点与维护

| 设置 | 说明 |
|------|------|
| **站点名称** | 浏览器标题、页头、登录页显示 |
| **列表列数（PC 端）** | 每行卡片数。**选「跟随模板默认」(0) 时**，才由模板编辑器的列数决定 |
| **播放页字段智能归一化（TypeSafe）** | 把地区/语言/类型/更新状态这类「同一份数据多种写法」的字段统一成规范值，并判定内容分级。**默认开启**；关掉后全部按上游原始值展示，页面照常工作 |
| **容量档位（极致低功耗）** | 决定各缓存目录的硬上限：`紧凑（1 GB 空间）`≈132 MB、`标准（5 GB 及以上）`≈387 MB、`自动探测`。**磁盘 ≤1 GB 请手动选紧凑** —— 不少主机的自动探测拿到的是整机磁盘而不是你的配额。见 [极致低功耗模式](lowpower.md) |
| **清理系统缓存** | 五项可勾选：接口响应缓存、字段归一化记录、**OPcache**、页面静态缓存、图片本地缓存。见下方「清理系统缓存」 |
| **导出 JSON / 导入配置** | 站点设置、模板样式、分组、数据源的备份与迁移。见下方「配置导入导出」 |

#### 清理系统缓存（含 OPcache）

| 勾选项 | 清什么 | 影响 |
|--------|--------|------|
| 接口响应缓存 | `runtime/cache/*.json` | 下次访问重新请求上游 |
| 字段归一化记录 | `enrich` 表 | 播放页归一化重新算一次 |
| **OPcache** | PHP 脚本缓存 | **磁盘上新改的文件立即生效** |
| 页面静态缓存 | `c/<时间桶>/*.html` | 下次访问重新渲染。**改了模板 / 样式却没变化时勾它**（正常情况下写配置会自动作废，这只是手动兜底） |
| 图片本地缓存 | `static/imgcache/` | 封面从上游重新拉一次。**清掉只是「每张图再付一次 EP」，功能永不缺失** |

> **「传了文件前台没变化」就是第三项在作怪。** 虚拟主机常设
> `opcache.validate_timestamps=0` —— 永不自动重新校验，**等多久都没用**。
> 状态行会直接告诉你是不是这个原因（会显示「且 validate_timestamps=0」）。
> 点一次「清理系统缓存」即可，等价于调用 `opcache_reset()`。
> 若后台显示「未安装 OPcache 扩展」或「受 restrict_api 限制」，
> 说明这个按钮管不了它，需要在主机面板里重启 PHP。

#### 配置导入导出

**导出**（`admin.php?export=1`）产出 JSON 附件：

```json
{
  "format": "vodhub-config",
  "version": 1,
  "schema_version": 5,
  "include_secrets": false,
  "settings": { "site_title": "...", "site_template": "default", ... },
  "groups":   [ { "id": 1, "name": "影视", "sort": 10 } ],
  "sources":  [ { "name": "...", "api_url": "...", "group_id": 1, ... } ]
}
```

| 内容 | 是否导出 |
|------|---------|
| 站点设置、模板样式变量（`tpl_vars_*`）、归一化开关 | ✅ |
| 分组、数据源（含接口地址、图片代理、白名单） | ✅ |
| `schema_version` | ❌ 由表结构迁移负责 |
| 管理密码哈希、访问密码哈希、`enrich_api_key` | ⚠️ **默认不导**，勾选「同时导出密码哈希与 API 密钥」才带 |

**导入**两种方式：

| 方式 | 行为 | 适用 |
|------|------|------|
| **合并**（默认） | 按 `api_url` 匹配已有数据源，只新增/更新，不删除 | 往现有站点追加接口 |
| **覆盖** | 清空现有分组与数据源，完全按文件重建（前端二次确认） | 换机迁移、灾备还原 |

导入规则：

- **分组 id 自动重映射** —— 新旧库的自增 id 不可能一致，源的 `group_id` 会跟着改
- 文件里**没带密钥**时，后台密码与访问密码**保持不变**
- `schema_version` 永不写入，避免和表结构迁移打架
- 非法条目（缺名称、地址非 `http(s)://`）逐条跳过，不让一条坏数据废掉整次导入
- 全程在**事务**内执行，出错自动回滚
- 导入后自动清空接口缓存（分组/源可能全变了）

> 支持**上传 .json 文件**或**直接粘贴**，文件优先。体积上限 2 MB。

#### 列数优先级（重要）

```
站点设置「列表列数」非 0   ──> 用它（最高优先级，覆盖一切）
        │
        为 0（跟随模板默认）
        ↓
模板编辑器改的列数         ──> 用它
        │
        没改过
        ↓
theme.json 里的 columns     ──> 用它
        │
        没有
        ↓
CSS 里的兜底值              ──> 用它
```

> 调模板列数没反应时，**第一件事就是回去看站点设置是不是设成了具体数字**。

## 缓存策略

| 数据 | 有效期 | 存储位置 |
|------|--------|---------|
| 列表 / 详情 | 30 分钟 | `runtime/cache/*.json` |
| 分类（`ac=list`） | 24 小时 | `runtime/cache/*.json` |
| 字段归一化结果 | 30 天 | `runtime/data.db` 的 `enrich` 表 |
| 字段归一化失败标记 | 10 分钟 | 同上（负缓存，避免端点故障时每个播放页都卡超时） |

- 缓存文件写入带 `LOCK_EX`，极端并发下不会写坏
- **上游故障时自动降级用旧缓存**（过期了也用），保证页面能开
- 「清空全部缓存」删的是这些 JSON 文件，**不影响数据库配置**
- 每个数据源删除时会顺带清掉它自己的缓存

### 缓存占用

后台「站点与维护 → 极致低功耗状态」会显示磁盘可用百分比、当前档位、
各项上限与实际占用。**磁盘是免费主机上唯一决定性的容量配额**，
而且它满掉不会表现为变慢，而是逐层崩坏（图片写不进 → 页面缓存写不进 →
接口缓存写不进 → SQLite 白屏 → 会话失效）。

所以本项目给**每个**运行期目录都设了硬上限，并配了 8% 水位红线
（低于就停止写入页面与图片缓存，**降速但不停摆**）。

如果发现异常增长：

1. 后台勾「页面静态缓存」「图片本地缓存」清理
2. 检查容量档位是不是选错了（1 GB 空间应选紧凑）
3. 确认 `runtime/`、`c/`、`static/imgcache/` 的权限正常（不能只读，否则清不掉）

## 存储了什么

### `runtime/data.db`（SQLite）

| 表 | 内容 |
|----|------|
| `settings` | 站点名、密码哈希、模板设置、样式变量、`schema_version` |
| `sources` | 数据源：名称、地址、排序、备注、绑定模板、分组、图片代理开关、白名单 |
| `groups` | 分组：名称、排序 |
| `enrich` | 播放页字段归一化结果，按（数据源 ID + 影片 ID）缓存 |

**含敏感信息**：管理员密码哈希、访问密码哈希、你配置的所有接口地址。

> ⚠️ 这个文件**绝不能提交进 Git，也不能通过 URL 访问**。`.htaccess` / Nginx 配置已拦截，`.gitignore` 也已排除。

### `runtime/cache/*.json`

上游接口的响应缓存。**可以随时全删**，程序会自动重建。

### `c/<时间桶>/*.html`（页面静态缓存 · 1.3.0）

前台页面的渲染结果，由 Apache 直出（命中时 **0 个 PHP 进程**）。
**可以随时全删**，程序会自动重建。

- 每小时换一个桶目录，**自动过期**，无需 cron；
- 超过 2 小时的桶由 `includes/guard.php` 删除；
- **任意后台配置写入都会全量作废**（`setSetting()` → `pcClear()`）；
- 开启访问密码时**不读不写**（安全红线，见 [极致低功耗模式](lowpower.md)）；
- 已加入 `.gitignore`。

### `static/imgcache/`（图片代理本地副本 · 1.3.0）

代理取过的封面，之后由 Apache 静态直出（**0 EP、0 出站**）。
**可以随时全删**，下次访问会重新拉一次。

- 超出档位上限按 `filemtime` LRU 淘汰，**淘汰是自愈的**（那张图再付一次 EP）；
- 落盘失败时静默降级回 `img.php` 转发，功能不受影响；
- 已加入 `.gitignore`。

### 表结构迁移

`db.php` 用 `settings.schema_version` 记录版本，每次启动检查并按需升级：

```
v1  sources 基础表
v2  sources 增加 template 列
v3  新建 groups 表 + sources.group_id
v4  sources 增加 img_proxy / img_hosts
v5  新建 enrich 表（字段归一化缓存）
```

**升级程序时不需要手工改数据库**，老数据完全不受影响。

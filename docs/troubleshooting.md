## 页面问题

### 整站白屏 / 报错

**第一步永远是看报错文字**。程序的 `config.php` 顶部有版本保护，会把环境问题变成明确提示：

| 你看到的 | 原因 | 解决 |
|---------|------|------|
| 「需要 PHP 8.0 及以上」+ 当前版本号 | PHP 版本过低 | 面板切换到 8.0/8.1/8.2/8.3 |
| 「缺少必需的 PHP 扩展」 | 没装 `curl` 或 `pdo_sqlite` | 面板里勾选启用这两个扩展 |
| 纯白屏、无任何文字 | `display_errors` 被关 + 有致命错误 | 见下方「打开错误日志」 |

**打开错误日志**：

```bash
# 临时开启显示错误
ini_set('display_errors', '1');   // config.php 末尾

# 或看 PHP 错误日志
tail -f /var/log/php8.2-fpm.log
tail -f runtime/php_errors.log    # 部分环境
```

> ⚠️ 找到问题后请把 `display_errors` 关回 `0`，生产环境不该把错误暴露给访问者。

### 前台 500 空体 + 后台提示「无法显示（Call to undefined function disk_total_space()）」

**现象**（InfinityFree 实测，`hop.free.je`）：

| 项 | 表现 |
|---|---|
| 前台 `index/list/search/play/history` | **500 + 空响应体** |
| `/static/*`、`/robots.txt` | 200 ✅ |
| `/admin.php`、`/img.php`、`/enrich.php` | 正常 ✅ |
| 后台「极致低功耗状态」 | ⚠️ 无法显示（**Call to undefined function disk_total_space()**） |
| 下方「🧹 系统缓存」 | **照常可用**（故障隔离生效了） |

**根因**：主机把 `disk_free_space` / `disk_total_space` 放进了 **`disable_functions`**
（免费主机常见，InfinityFree 实测如此）。调用时抛的是 **`Error`**。

> **`@` 只能抑制 Warning，抑制不了 `Error`。** 所以代码里那句
> `@disk_total_space()` **没有任何保护作用**，Error 直接冒到 `renderTemplate()`
> 把整站前台打死。而后台有 `try/catch`，所以**两边表现不一致** —— 这正是定位线索。

**为什么只有 5 个前台页挂**：只有它们走 `renderTemplate()` → `pcSyncGate()` →
`guardCaps()` → `guardDisk()`。`img.php` 不走，`enrich.php` 只 require 不调用，
`admin.php` 有 try/catch。

**怎么修**（1.3.0 已修，第 4 轮）：`guardDisk()` 加 `function_exists` + `try/catch`
双层防护，探测不到就**按后台「容量档位」设置**跑，硬上限仍然生效。

**你只需要**：用最新包覆盖 `includes/guard.php`、`admin.php`、`img.php`（或整体覆盖），
然后到后台**手动选容量档位**（探测不到时 `auto` 取紧凑档）。

**确认是哪一类问题**：跑 `vp.php` 看 **H 节** —— 它列出 21 个关键函数，
直接标出哪些被 `disable_functions` 禁了，并给出 `php.ini disable_functions` 原值。

**口诀**：

| 后台提示里的错误 | 真正原因 | 处理 |
|---|---|---|
| `Call to undefined function disk_*` | **主机禁用函数**，与升级包无关 | 手动选容量档位 |
| `Call to undefined function 其它` | 主机禁用了别的函数 | 跑 `vp.php` H 节 |
| `Undefined constant ...` | **`config.php` 是旧版** | 补传 `config.php` |
| `Failed opening required ...` | **升级包缺文件** | 按 B 节标 `缺!` 的补传 |

### 升级 1.3.0 后首页 500（静态文件却正常）

**现象**（2026-09-28 线上实测）：

| 路径 | 结果 |
|------|------|
| `/static/style.css`、`/robots.txt` | ✅ 200 |
| `/admin.php` | ✅ 200（能登录） |
| `/img.php?u=&s=1` | ✅ 400 `missing url`（**这是正常响应**） |
| `/enrich.php?...` | ✅ 200 JSON |
| **`/index.php`、`/list.php`、`/search.php`、`/play.php`、`/history.php`** | 🔴 **500 + 空响应体** |

**根因**：**`config.php` 还是 1.2.0 旧版** —— 1.3.0 给它新增了 4 个常量
（`APP_VERSION`、`CACHE_TTL_NEG`、`PAGE_CACHE_DIR`、`IMG_CACHE_DIR`）。

`renderTemplate()` 第一行 `pcSyncGate()` 要用 `PAGE_CACHE_DIR`，旧版没有 →
`Error: Undefined constant "PAGE_CACHE_DIR"`；而 `display_errors=Off`
让它**不打印**，于是变成「**500 + 空体**」—— 既没有报错文本，也没有半截页面。

**为什么只有那 5 个页面挂**：只有它们走 `renderTemplate()`。
`img.php` 不走、`enrich.php` 只 `require` 不调用、`admin.php` 自己输出 HTML、
静态文件根本不进 PHP —— 所以它们全部正常。**这正是定位的关键线索。**

**判别口诀**：

> 静态文件 200 + 后台 200 + **只有前台页空体 500** ⇒ **先去补传 `config.php`**

**怎么修**：

```bash
# 立刻恢复：只补这一个文件就够（根因就在它）
# 从升级包把 config.php 覆盖到站点根，然后清一次 OPcache，刷新
```

**根治（1.3.0 后续已修）**：`includes/guard.php` 与 `includes/client.php`
现在**自带这三个常量的默认值**，漏传 `config.php` 时前台**不再 500**，
只是降级（容量档位与版本号读不到）；后台「极致低功耗状态」会显示
「⚠️ 无法显示（config.php 是旧版…）」提示你补传。

> **排查顺序建议**：先看静态文件与后台是否正常 —— 如果它们也 500，
> 那问题在 `.htaccess`（比对包里的版本）；如果只有前台挂，就是 `config.php`。

### 报 `foreach() argument must be of type array|object`

某个函数把非数组传给了 `foreach`。**看完整报错里的文件名和行号**，那一行就是问题所在。

典型原因：函数返回 `int`（如 `preg_match_all()` 返回匹配数）却被直接遍历。

### 提示「未知操作」

后台某个按钮点了没反应。

1. **看完整提示**：新版会显示 `未知操作：收到 action=xxx（映射表 N 项）`
   - `action=(空)` → 表单字段没提交上来
   - `action=xxx` 但映射表项数不对 → **服务器上的 `includes/admin-actions.php` 是旧版本**
2. **最可能的原因**：文件没上传成功。确认 `htdocs/includes/admin-actions.php` 存在且是最新版
3. 上传后仍不行 → 主机面板可能有 **opcache**，在面板里「重载 PHP」或等几分钟

### 提示「表单令牌已过期」

CSRF 校验失败，通常是页面开太久再提交。

**解决**：刷新页面重新提交即可，不会丢数据。

### 管理后台登不进去

1. 密码确认没打错（注意大小写、输入法）
2. 默认密码是 `admin123` —— 如果你从没改过，就是它
3. 换个浏览器 / 隐私模式试（排除 cookie 被禁用）
4. 确认 `session.save_path` 可写

> 密码忘了没有「找回」—— 单用户自托管项目没有邮箱。只能清库重设：
> ```bash
> sqlite3 runtime/data.db "DELETE FROM settings WHERE key='admin_password';"
> # 重启后台后用默认密码 admin123 登录，然后立刻改掉
> ```

### 访问前台要输密码，但密码忘了

同上，清掉访问密码即可：

```bash
sqlite3 runtime/data.db "UPDATE settings SET value='0' WHERE key='access_enabled';"
```

### 前台空白但后台正常

多半是模板路径问题。

1. 确认 `templates/` 目录完整（和 `index.php` 同级）
2. 看报错是否提示「模板页面缺失：xxx」→ 补齐对应文件
3. 后台 → 模板管理 → 确认站点默认模板存在

## 图片相关

### 封面全裂 / 全是占位图

按顺序试：

1. **直接在浏览器打开图片地址** —— 如果这里也打不开，是上游图片挂了，不是你的问题
2. **能打开，但站内裂图** → 大概率是**防盗链**
   - 后台 → 数据源 → 编辑 → **勾选「启用图片代理」**
   - 白名单**留空即可**（内网地址仍会自动拦截）
   - 保存后刷新前台
3. **还不行** → 点该源的**「识别图域」**，把实际图片域名写进白名单
4. **部分图片裂** → 检查白名单是否填得太窄，把多余的域名去掉

**打开 `img.php?...` 这条链接本身看返回的字**，它会直接告诉你是哪一层拦的：

| 返回 | 含义 | 处理 |
|------|------|------|
| `200` + 图片 | 代理正常 | 看别处 |
| `400 missing source param (s)` | 链接里确实没有 `s=` | 从页面上重新取地址（右键图片 → 复制图片地址） |
| `404 source not found (s=N)` | 数据源被删过，或 id 对不上 | 回后台确认该源还在 |
| `403 proxy disabled for source N [名称]` | **这个源确实没勾选代理** | 勾上保存 |
| `403 host not allowed` | 图片域名不在白名单里 | 点「识别图域」，或把白名单清空 |
| `403 private address blocked` | 目标是内网/保留地址，SSRF 拦截（**这是正常的**） | 不能绕过 |
| `502 fetch failed` | 你服务器访问不到那张图 | 查网络 / 上游 |
| `415 not an image` | 上游返回的不是图片 | 上游异常 |
| 页面满是 Fatal error | — | 见下方「代理后满屏 Fatal error」 |
| `img.php 开头有多余输出…` | 文件带 UTF-8 BOM 或 `<?php` 前有空行 | 用「UTF-8 无 BOM」重新保存，并删掉 `<?php` 前后的空行 |
| 图片不显示，但链接打开是正常的图 | 浏览器缓存了旧的失败响应 | `Ctrl+Shift+R` 强制刷新 |
| 传了新 img.php 还是老样子 | **OPcache 没刷新** | 后台 → 站点与维护 → **清理系统缓存**（勾上 OPcache）→ 保存。见下方「传了文件前台没变化」 |

> 详细原理见 [数据源接入 · 图片代理](api-sources.md#图片代理与防盗链)

### 代理一开就满屏 Fatal error

`img.php` 早期版本漏了 `require includes/functions.php`，导致图片抓回来之后在
「自动学习域名」那一步调用 `learnImgHost()` 直接 `Call to undefined function` ——
**取图成功却一个字节都发不出去**，表现为开关一开图片全裂。升级到 v1.1.1 及以上即可。

> 注意：这个错误在**浏览器里看不出来**，只会看到封面变占位图。要确认就直接打开
> 一条 `img.php?...` 链接，或看服务器错误日志。

### 传了文件，前台没变化

**九成是 OPcache。** 虚拟主机常把 `opcache.validate_timestamps` 设为 `0`，
意思是「永不自动重新校验」—— 换完文件**等多久都没用**，跑的永远是旧代码。

判断：

1. 后台 → 站点与维护 → 看「**OPcache**」那一行
2. 如果写着「**且 validate_timestamps=0（永不自动重新校验）**」，就是它
3. 勾上 **OPcache** → 点「清理系统缓存」→ 再刷新页面

等价于调用 `opcache_reset()`，磁盘上新改的文件立即生效。

> 实测复现：`validate_timestamps=0` 下改文件 → 请求仍是旧代码 →
> 等 4 秒还是旧代码 → 点该按钮 → 立即变成新代码。
>
> 如果按钮提示「未安装 OPcache 扩展」或「受 restrict_api 限制」，
> 这条路走不通，得去主机面板重启 PHP 或改 `opcache.validate_timestamps`。

### 图片代理开了反而更慢

正常 —— 代理会增加你服务器的出站请求。如果上游没有防盗链，**关掉代理**。

### 封面被裁切 / 上下留白

**封面比例和模板不匹配**。

| 现象 | 说明 | 解决 |
|------|------|------|
| 两侧被裁 | 竖图塞进了宽图框 | 换 `default`（2:3）或调大比例值 |
| 上下留白 | 横图塞进了竖图框 | 换 `bilibili`（16:9）或调小比例值 |

- 快速解决：**给这个源绑定另一个模板**
- 精细调整：后台 → 模板管理 → 编辑样式 → 「封面高度比例」

参考值：16:9 → `56.25`，3:4 → `75`，2:3 → `150`，1:1 → `100`

## 模板相关

### 数据源换了模板，前台没变化

这是最常见的疑问。**按这个顺序查**：

1. **你点的是哪个页面？**
   - 首页（没有 `?source=N` 参数）→ 显示**全部源**，用的是**站点默认模板**，本来就不会变
   - **点该数据源的标签**（地址带 `?source=N`）→ 这里才会用该源绑定的模板

2. **绑定的模板和站点默认模板一样吗？** → 换个明显不同的试试（如 `bilibili` 是浅色，一眼能看出来）

3. **浏览器缓存** → `Ctrl + Shift + R` 硬刷新，或 F12 勾选「停用缓存」再刷新

4. **进了列表页？** → 点进任意分类（`list.php`）也会用该源的模板

5. **代码是不是最新的？** → 确认 `index.php` 已更新（旧版首页不传递数据源，导致永远用站点默认模板）

### 后台改了样式，前台没生效

| 检查项 | 说明 |
|-------|------|
| `header.php` 注入了吗 | 必须有 `<?php foreach ($tplMeta['vars'] ...)` 那段 |
| CSS 用 `var()` 了吗 | 写死的字面量改了也没用 |
| 变量名一致吗 | 保存的键必须和 CSS 里 `var(--xxx)` 完全一致 |
| 浏览器缓存 | 硬刷新 |
| 站点列数覆盖了吗 | 「站点设置 → 列表列数」非 0 会覆盖模板编辑器的列数 |

→ 完整机制见 [模板开发 · CSS 变量编辑器](templates.md#css-变量编辑器)

### 某个编辑框没显示

**正常现象**。编辑器只显示模板 CSS 里**真的被 `var()` 引用**的维度。

想让它出现，把 CSS 从 `aspect-ratio: 16 / 9` 改成 `aspect-ratio: var(--xxx-cover-ratio, 16 / 9)`。

### 列数改了没反应

**站点设置的列数优先级更高**：

后台 → 站点与维护 → 列表列数 → 改成 **「跟随模板默认」(0)** → 再去改模板编辑器的列数。

### 「恢复默认样式」后还是没变

1. 硬刷新浏览器
2. 确认改的是**当前前台正在用的那套模板**（不是你编辑的另一套）
3. 清空缓存：后台 → 站点与维护 → 清空全部缓存

### 报「模板页面缺失：xxx」

模板缺 `xxx.php` 且 `default` 里也没有。补齐该文件。

## 后台问题

### 保存后表单跳回「添加数据源」

正常情况下保存后应保持在**编辑态**。如果跳回新增态：

1. 确认顶部有 `✅ 已更新数据源` 提示（有 = 保存成功了，只是显示问题）
2. 去上方表格看该行的值是否已更新
3. 仍跳回 → 上传最新 `admin.php`

### 保存后没提示

可能是操作成功但消息被 3 秒淡出动画隐藏了（`static/app.js`）。刷新页面再看表格确认。

### 某个按钮点了没反应

1. 看是否弹了确认框被忽略
2. 看顶部有无提示
3. F12 → Console 看有无 JS 报错

### 后台很卡

- 数据源太多 → 给它们**分组**，前台标签就不会挤成一堆
- 缓存文件太多 → 「清空全部缓存」
- 测试按钮慢 → 是上游接口慢，不影响你

## 缓存与性能

### 更新了内容但前台不显示

**是缓存**。列表/详情缓存 **30 分钟**，分类缓存 **24 小时**。

- 立即看：后台 → 站点与维护 → **清空全部缓存**
- 改 TTL：`config.php` 里的 `CACHE_TTL`（秒）

### 上游挂了整站打不开

**设计如此会自动降级**——上游故障时用过期缓存顶着。

1. 缓存里有数据 → 页面还能开，只是内容旧
2. 缓存也没有 → 确认「清空全部缓存」不要点（会把兜底数据也删了）

### 改了配置 / 样式，前台没反应（1.3.0 页面静态化）

**现象**：后台改了站点名称、主题色、列数、绑定了别的模板，刷新前台**纹丝不动**。

**原因**：1.3.0 起前台页会落盘到 `c/<时间桶>/` 由 Apache 直出，旧文件没被作废。

**处理**（按顺序试）：

1. 后台「系统缓存」勾选**页面静态缓存** → 清理；
2. 若仍不行，`rm -rf c/`（或在面板文件管理里删掉 `c/` 目录）；
3. 仍然不行 → 说明 `setSetting()` → `pcClear()` 这条链断了，请提 Issue。

> **正常情况下不需要手动做**：任意后台配置写入都会自动全量作废 `c/`。
> 这是 1.3.0 的硬验收项（A19），如果能复现说明有 bug。

### 第二次访问没有变快（静态化没生效）

**排查顺序**：

```bash
# ① 有没有生成静态文件
find c -name '*.html' | wc -l          # 0 → 没生成，看下面「权限」
# ② 是不是 rewrite 没生效
#    有文件但第二次还是慢 → .htaccess 的 -f 没匹配（多半是时区或 AllowOverride）
```

| 情况 | 判断 | 处理 |
|------|------|------|
| `c/` 里没有文件 | 写入失败或 `pcEnabled()` 为 false | 看后台「极致低功耗状态」的「页面静态化」是否显示**已启用**；检查 `c/` 是否可写；确认没有开启访问密码 |
| 有文件但每次都慢 | `.htaccess` 的 `-f` 没匹配 | 确认 `AllowOverride` 允许 `FileInfo`/`All`（见 [.htaccess 不生效](#htaccess-不生效apache)）。**时区对不上是正常的**——PHP 已把应用时区/主机 ini 时区/UTC 三种候选桶都写了，若服务器用的是第四种时区，退化到第 2 层读盘（1 个进程 × 约 3 ms），功能完全正常 |
| 页面结构对但**内容是旧的** | 桶还没到一小时 | 这是设计边界：静态粒度最细 1 小时。搜索永远实时，翻页与点开播放是新 URL 会立即生效 |

### 封面莫名其妙长期全裂（故障页被缓存）

**现象**：某段时间上游或本站图片出过问题，之后**即使恢复了封面也一直是占位图**。

**原因**：4xx/5xx 响应被浏览器或 `ExpiresByType image/*` 缓存了「保鲜」。

**处理**：1.3.0 已给 `img.php` 的所有错误响应加 `Cache-Control: no-store`。
若现象仍存在：

1. 确认上传的是 1.3.0 的 `img.php`（`curl -I` 看 `X-Img-Proxy` 头）；
2. 后台勾**图片本地缓存**清理；
3. 浏览器硬刷新（Ctrl+Shift+R）。

### 磁盘被缓存吃满

缓存都在 `runtime/cache/`：

```bash
du -sh runtime/cache/
rm -rf runtime/cache/*        # 或用后台的「清空全部缓存」
```

### 后台找不到「数据备份还原」（配置导入导出）

**先确认它叫什么、在哪**：功能在后台**最底部**，标题是
**「📦 配置导入导出」**，两个按钮是 **「⬇ 导出 JSON」** 和 **「⬆ 导入配置」**
—— **它不叫「备份还原」**，按字面搜是找不到的。位置在
`⚙️ 站点与维护 → 🔵 极致低功耗状态 → 🧹 系统缓存 → 📦 配置导入导出`，
是**整页最后一个段落**，页面很长，很容易滚不到底。

**它是 v1.2.0 才加入的**（`includes/config-io.php` 也是 v1.2.0 才有）——
`admin.php` 若停在 1.1.x 或更早，源码里压根没有这一段。

#### 判定：跑 `vp.php` 的 **G 节**

| G 节结果 | 结论 | 处理 |
|---------|------|------|
| **「📦 配置导入导出」= 有**，但你后台看不到 | **页面在它之前被截断了** | 回 C 节看 `pcSyncGate()` 是否抛错、E 节看 OPcache、B 节看是否有文件「旧!」 |
| **「📦 配置导入导出」= 缺!** | **`admin.php` 是旧版** | B 节 md5 会同时标 `旧!`；用最新包覆盖 `admin.php` |
| 「入口标记」里 `name="export"` / `import_config` 缺 | 同上 | 同上 |

**口诀：源码有 + 后台没看到 = 截断；源码就没有 = `admin.php` 旧版。**

#### 快速旁路验证（不看 UI，直接测功能本身）

已登录的情况下直接访问：

```
https://你的域名/admin.php?export=1
```

| 返回 | 结论 |
|------|------|
| **下载了一个 JSON 文件** | ✅ 功能正常，只是 UI 段没渲染 → **截断**，看 G 节找截断点 |
| 跳到登录页 | 会话问题，重新登录再试 |
| 500 | `includes/config-io.php` 或其依赖有问题 → 看 B 节文件指纹 |

#### 顺带看另外两段还在不在

「🔋 极致低功耗状态」（1.3.0+）与「🧹 系统缓存」（1.2.0+）紧挨在它上面：

- **三段全缺** → `admin.php` 是 **1.1.x 或更早**
- **只有「配置导入导出」缺** → 不可能（它在最后，前面都在说明没截断）→ 一定是 `admin.php` 旧
- **「极致低功耗状态」缺、其余在** → `admin.php` 是 **1.2.0**

### 点了「清理 OPcache」还是不生效（传了新文件仍跑旧代码）

**现象**：手动清理显示 `✓ 缓存清理成功`，或后台按钮提示已重置，
**但首页依旧是旧代码 / 依旧 500**。同时状态显示 `缓存满=是`、
`已用 511.97 MB / 空闲 0.03 MB`、`已缓存脚本 13955`。

**三个原因，按可能性排序**：

| # | 原因 | 判定 | 处理 |
|---|------|------|------|
| 1 | **`opcache_reset()` 只清了一个子进程** | `vp.php` A 节 SAPI = `apache2handler` | **用面板「重启 PHP / 重启站点 / 重启 Apache」**，不要只点按钮。prefork + mod_php 下每个子进程有独立 OPcache |
| 2 | **OPcache 内存已满**，新编译结果写不进去 | `vp.php` E 节「缓存已满 = 是」 | 面板 `opcache.memory_consumption` 512 → **1024**，或重启 PHP |
| 3 | **`validate_timestamps=0`**，永不检查文件修改时间 | `vp.php` E 节该值为 `0` | 面板 php.ini 设 `validate_timestamps=1`、`revalidate_freq=0`，以后**无需再清** |

**最快的一条**：面板重启 PHP。这三条一次性全解决。

> **脚本数上万（如 13955）说明这个 OPcache 被同机多个站点共用**，
> 不是你一个站撑满的 —— 所以「我清了」往往只清了自己那部分。

**注意 `.user.ini` 的适用范围**（`vp.php` A 节直接给）：
`apache2handler`（mod_php）下 **`.user.ini` 无效**，只有 `.htaccess` 的 `php_value` 生效；
`cgi-fpm / litespeed` 下反过来。两边都不生效时靠 `includes/guard.php` 的运行时 `ini_set` 兜底。

### 升级包是不是旧的？（首页 500 / 后台段落消失 / 清理无效，可能是同一件事）

**一个判据**：升级包里**有没有 `vp.php`**。没有就是旧包 —— 1.3.0 在 2026-09-28
修过三轮，缺任意一轮都会出问题：

| 症状 | 缺哪一轮修复 | 根因 |
|------|------------|------|
| **首页 500 + 空响应体** | 缺「常量兜底」 | `config.php` 是旧版 → `pcSyncGate()` 抛 `Undefined constant`；`display_errors=Off` 让它变成空体 500 |
| **后台「🧹 系统缓存」整段消失** | 缺「故障隔离」 | 状态栏在旧 `config.php` 上 fatal，把紧随其后的系统缓存段一起截断 |
| 点了清理 OPcache 无效 | 与包无关 | 见上一节（多进程 / 满 / validate_timestamps） |

**定位顺序**（`vp.php` 会自动给出）：

```
1. vp.php B 节 → 哪些文件标了「旧!」「缺!」
2. vp.php C 节 → pcSyncGate() 是否抛错（= 首页 500 的直接死因）
3. vp.php A 节 → SAPI（决定 OPcache 配置从哪改）
4. vp.php E 节 → validate_timestamps 是否为 0、缓存是否已满
```

**统一处理**：**用最新包整体覆盖 44 个文件 → 面板重启 PHP → 按
`/static/style.css` 200 → `/admin.php` 200 → `/index.php` 200 顺序验证 → 删除 `vp.php`。**

### 后台「清理 OPcache」那一段不见了

**现象**：后台能打开，但「🧹 系统缓存」以及里面的 **OPcache 复选框与清理按钮**
整段消失，页面上半部分看着一切正常。

**原因**：这不是功能被删了 —— 是**页面在到达它之前就断了**。
1.3.0 新增了 `includes/guard.php`、`pagecache.php`、`imgcache.php`，
而且 **`config.php` 也改过**（新增 4 个常量）。只要这几个没传齐，
PHP 就会在中途致命错误；而生产环境 `display_errors=Off`，
**错误不会打印，页面只是无声无息地截断**。

**怎么判断**（三种情况，看页面末尾）：

| 页面末尾 | 缺什么 | 处理 |
|---------|--------|------|
| 有一块红框：**「⛔ 后台在此处中断：PHP 致命错误」**，带文件与行号 | 缺 `includes/*.php`（`require` 阶段就断了） | 按提示补齐 43 个文件 → 清 OPcache → 刷新 |
| 「🔋 极致低功耗状态」显示 **「⚠️ 无法显示（…常量 … 未定义）」**，下面「系统缓存」**正常** | **`config.php` 是旧版**（最常见） | 只补传 `config.php` 即可，系统缓存段已自动隔离不受影响 |
| 什么提示都没有、页面就是短一截 | 站上还是旧版 `admin.php` | 用升级包里的 `admin.php` 覆盖 |

**兜底**：即使上面都看不懂，直接把升级包的 **43 个文件整体重传一次**
（`升级说明.md` 第二节「整包覆盖，别挑着传」），这是 100% 有效的。

> 1.3.0 起，`admin.php` 顶部注册了 shutdown handler，**致命错误会显示在页面末尾**
> （错误信息 + 文件 + 行号），不再是静默截断 —— 所以下次再遇到应当直接能看到原因。

### 后台提示「磁盘即将写满」（水位保护模式）

**原因**：可用空间低于 **8%** 红线。SQLite 接近满盘会报 `disk is full`，
会话文件写不进去会让所有登录态失效 —— 所以本项目主动**停止写入页面与图片缓存**。

**站点不会挂**：页面走 PHP 渲染、图片走 `img.php` 转发，**全部功能正常**，
只是 EP 会回升。这叫「降速但不停摆」。

**处理**：

1. 后台勾**图片本地缓存** + **页面静态缓存**清理；
2. 确认**容量档位**选对（1 GB 空间 → 紧凑，上限 132 MB）；
3. 检查是不是上传了 `docs/` 之类的无关大文件；
4. 水位恢复到 8% 以上会自动退出保护模式。

### 调整缓存时间

```php
// config.php
define('CACHE_TTL',      1800);   // 列表/详情：默认 30 分钟
define('CACHE_TTL_TYPE', 86400);  // 分类：默认 24 小时
```

改完立即生效。

## 环境与部署

### 权限问题

| 症状 | 原因 | 解决 |
|------|------|------|
| 提示无法创建数据库 | `runtime/` 不可写 | `chmod -R 755 runtime` |
| 缓存清不掉 / 不生效 | `runtime/cache/` 只读 | `chmod -R 777 runtime/cache` |
| 白屏且无报错 | 目录权限错误 | 确认站点根目录可读 |

**只需要 `runtime/` 可写**，其他保持 `644`/`755` 即可。

### `.htaccess` 不生效（Apache）

1. 确认 `AllowOverride All`（或至少 `FileInfo`）—— 虚拟主机主配置里
   ```apache
   <Directory /var/www/VodHub>
       AllowOverride All
   </Directory>
   ```
2. 确认 `mod_rewrite` 已启用：`a2enmod rewrite && systemctl restart apache2`
3. 验证：
   ```bash
   curl -I https://你的域名/runtime/data.db   # 期望 403
   ```

> 没生效也不影响功能，但**运行期数据会暴露在公网**，请务必修好。

### Nginx 下 `.htaccess` 不起作用

Nginx 不读 `.htaccess`，访问控制需要写进 server 块 —— 见 [部署指南 · Nginx](deployment.md#nginx--php-fpm)。

### 跳转路径不对（反向代理 / 子目录）

程序用相对链接，一般自动适配。如果异常，检查代理是否正确传递了 `Host` 和 `X-Forwarded-Proto` 头。

### 改了文件不生效

**opcache** 在缓存旧的 PHP 字节码：

```bash
# 立即刷新
sudo systemctl restart php8.2-fpm

# 或临时关闭
ini_set('opcache.enable', '0');
```

虚拟主机通常在面板里有「重载 PHP」按钮。

### 页面静态化与访问密码的取舍

**现象**：后台「极致低功耗状态」显示页面静态化**未启用**，并注明
「已开启访问密码 → 按安全要求自动停用」。

**这不是 bug**：`.htaccess` 直出会**完全绕过 `requireAccess()`**，
而 `.htaccess` 无法验证会话是否真的鉴权通过（伪造一个 cookie 就能绕过）。
所以开启访问密码时**自动停用**，页面全部走 PHP（1 个进程 × 约 3 ms），
**仍远好于优化前**，且其余五个支柱（图片本地化、富化内联、零阻塞、
微秒化、护栏）**全部继续生效**。

不需要你记住这件事，也不会误开 —— 开关联动是自动的。

### 静态资源没有缓存头

| 服务器 | 需要 |
|--------|------|
| Apache | `mod_expires` + `mod_headers`（都启用） |
| Nginx | 在 server 块里写 `expires`（`.htaccess` 无效） |

缺失时**不影响功能**，只是每次都要重新下载。
